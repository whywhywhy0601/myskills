# 笔记模板

模板是骨架，不是填空卷。下面每个小节都解释了"写什么才有用"；写的时候可以合并或省略不适用的小节，但不要写成一串没有判断的复述。

---

## 一、速读卡片

三种模式都先写这一节。它的作用是让整个阅读记录可以被快速浏览——以后翻 `阅读记录.md`，只看卡片就能决定要不要读全文。

```markdown
### 速读卡片

**一句话**：<这篇论文真正的新东西，以及它凭什么成立>
**问题**：<在它之前，什么地方不够好 / 卡在哪里>
**做法**：<核心机制，2–3 句，配一个类比>
**证据**：<最强的一两个结果：数据集、指标、对比对象、数字>
**代价**：<作者承认的局限 + 你发现的；具体到什么场景下会失效>
**判断**：**<强烈推荐精读 / 值得一读 / 按需 / 跳过>** —— <对谁有用、为什么>
```

各行的写法：

- **一句话**不是标题复述，而是"结论 + 成立的理由"。如果这句话删掉论文名还能成立，说明写空了。
- **问题**要写到具体的失败模式，比如"RNN 必须顺序计算，导致训练无法并行，长序列上尤其慢"，而不是"现有方法存在不足"。
- **做法**最多三句。先讲机制，再讲它为什么解决上面的问题；类比是给三个月后的自己省时间的。
- **证据**必须带数字。只有一个数字时，选最能支撑核心主张的那个，并说明对比对象是谁。
- **代价**分两层：作者自己承认的，和你读出来的。后者往往更有价值，但要标明是你的判断。
- **判断**只能四选一，并给出适用人群。不要写"有一定价值"这种不承担判断的结论。参考标准：
  - **强烈推荐精读**：领域内几乎必读，或方法可迁移到你正在做的事；读它能改变你的做法。
  - **值得一读**：有具体可用的点（一个模块、一组实验、一个失败模式），但不必逐段读。
  - **按需**：只有做某个特定任务 / 需要某个数字时才翻，平时不值得投入时间。
  - **跳过**：增量改进、证据不足，或结论已被更早的工作覆盖；说明跳过的理由，别只写"一般"。

正例：

> **一句话**：把 RNN 的顺序依赖换成纯注意力的并行计算，在翻译质量不降的前提下把训练时间缩短了一个数量级。
> **问题**：RNN/CNN 序列模型必须按时间步或感受野堆叠，长距离依赖路径长，且难以充分利用并行硬件。
> **做法**：编码器和解码器全部由多头自注意力 + 前馈层堆叠而成，位置信息靠正弦位置编码注入。
> **证据**：WMT14 英德 28.4 BLEU（此前最好约 26.4），英法 41.8 BLEU；8×P100 上大模型训练 3.5 天。
> **代价**：自注意力对序列长度是 O(n²)，长文档和高分辨率输入上显存与计算会先成为瓶颈；训练需要大量数据。
> **判断**：**强烈推荐精读** —— 做序列建模、想理解现代大模型基本结构的读者；如果只关心某个下游任务，读第 3 节和第 5 节即可。

反例（不要这样写）：

> **一句话**：本文提出了一种新颖的基于注意力的方法，取得了显著的效果提升。
> **判断**：有一定参考价值。

问题在于：没有具体机制、没有数字、没有可执行的判断。

## 二、精读笔记

在速读卡片之后。默认读者是"懂本领域基础、但不熟悉这个子方向"的人。

```markdown
### 精读笔记

#### 0. 元信息
- 论文：
- 作者 / 机构：
- 年份 / 会议或期刊：
- 版本：<arXiv v3 / 正式版 / 预印本>，阅读日期
- 链接 / 代码：
- 为什么读它：

#### 1. 问题与动机
- 要解决的具体问题：
- 之前的方法卡在哪：<引论文里的 baseline 或失败模式，不要泛泛说"存在不足">
- 作者的关键假设：
- 如果这个假设不成立，会怎样：

#### 2. 核心想法
<一段话：如果只能记住一件事，是什么。再给一个类比。>

#### 3. 方法拆解
<按数据流，或按训练/推理流程写。公式只在必要处出现，每个符号都解释。>
- 输入 / 输出是什么：
- 关键模块 1：作用、怎么算、为什么这样设计
- 关键模块 2：……
- 训练目标与优化细节：
- 推理时的流程与开销：

#### 4. 实验与结果

| 数据集 | 对比对象 | 指标 | 本文结果 | 对比结果 | 是否公平 |
|---|---|---|---|---|---|
| | | | | | |

- 主结果说明了什么：
- 消融实验支持了哪个设计选择：
- 哪些结果没有解释：

#### 5. 结论与适用边界
- 在什么条件下可信：
- 在什么条件下不成立：
- 迁移到别的任务需要改什么：

#### 6. 局限与可疑点
<作者承认的 / 你发现的 / 证据不足的，分开写。>

#### 7. 与我相关
- 可以直接用的：
- 需要改造才能用的：
- 值得追的引用或后续工作：

#### 8. 术语
| 术语 | 一句话解释 | 在本篇里的具体含义 |
|---|---|---|
| | | |

#### 9. 原文定位
- 核心方法：§3，p.4–6
- 主结果：Table 2，p.7
- 消融：§5.2，Table 3
- 关键图：Figure 1（p.2），Figure 3（p.8）
```

写法要点：

- **动机**要能回答"如果没有这篇论文，研究者会怎么做，为什么不够好"。写不出来，说明还没读懂。
- **核心想法**独立成段，不要和方法细节混在一起。判断标准：一个没读过论文的人看完这段，能说出"它的大招是什么"。
- **方法拆解**按流程写，不要按论文的小节顺序抄。抄顺序会让笔记和原文一样难读。
- **实验表**只放支撑核心主张的行。把论文里所有表格搬进来不会增加信息，只会稀释重点。
- **公平性**一栏值得认真填：baseline 是否是同一数据、同一预算下重训的？有没有用额外数据？这些是论文最常回避的地方。
- **局限**至少写三条，其中至少一条是自己发现的。写不出三条通常不是论文完美，而是读得不够。
- **原文定位**必须核对页码/章节号。这栏是整份笔记的"可验证性"来源。

## 三、问答

默认只回答被问到的内容，不重写整篇笔记。格式：

```markdown
**答**：<先给直接答案，一两句>

> 原文："……" —— §4.2 / Table 3 / p.7

<必要时的解释：为什么这样设计、和别处的关系、需要注意的例外>
```

规则：

- 先给结论，再给依据。用户问的是"是什么/为什么"，不是想看你重新走一遍检索过程。
- 引用原文时给位置；转述和直引要分清。
- 如果答案分散在多个章节，按逻辑组织，不要按页码顺序罗列。
- 原文没写清楚时，明确说"原文只说了 X，没有解释 Y"，然后给出你的推测并标明是推测。
- 如果用户是在读完笔记后追问，优先复用已有笔记里的定位；发现笔记有错，用"更正"的方式写回统一文件。

## 四、追加"补充"小节

同一篇论文再次阅读（复读、读了附录、看了代码、看到后续论文）时追加：

```markdown
### 补充 · 2025-11-21 · 读了官方代码

- 复读后的新理解：
- 之前写错的地方：更正：……
- 新发现的问题：
```

不要重写整篇笔记，也不要删除旧内容。保留"当时的理解"和"现在的修正"，对未来的自己更有用。

## 五、统一文件的索引

索引表由 `scripts/append_note.py` 维护，不要手改。格式如下，供排查问题：

```markdown
| 日期 | 论文 | 年份 | 深度 | 判断 | 标签 |
|---|---|---|---|---|---|
| 2025-11-21 | [Attention Is All You Need](#p-1706-03762) | 2017 | 精读 | 值得一读 | #transformer #attention |
```

- 链接锚点由 DOI / arXiv ID 生成；没有这两个标识时用标题哈希，保证稳定。
- 同一篇论文只占一行。补充内容不新增行。
