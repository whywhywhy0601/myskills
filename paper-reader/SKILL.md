# 论文阅读

读论文的目的不是"读完"，是拿到三样东西：**判断**（值不值得投入）、**结构**（它到底做了什么）、**连接**（和我有什么关系）。

好的笔记让三个月后的你不用翻原文就能想起关键点；坏的笔记只是把摘要换了个说法。这个 skill 的全部设计都是为了这个差别。

## 选模式

| 模式 | 用户通常怎么说 | 产出 | 篇幅 |
|---|---|---|---|
| 速读 | 看看这篇 / 值不值得读 / 这篇讲了啥 | 速读卡片：结论、贡献、关键数字、判断 | 300–500 字 |
| 精读 | 精读 / 做笔记 / 详细讲讲方法 | 速读卡片 + 结构化精读笔记 | 1500–3000 字 |
| 问答 | 它为什么用 X / baseline 是什么 / 这个公式啥意思 | 直接回答 + 原文定位，不重写整篇 | 按问题 |

判断规则：

- 用户明确说"精读 / 做笔记 / 详细讲" → 精读。
- 用户问某个具体点 → 问答。先读相关章节再答，不要凭标题、摘要或记忆猜；答完可以顺手把有价值的部分并入已有笔记。
- 用户只丢来一篇论文、没说读多深 → **先出一张速读卡片**，末尾问一句"要不要展开精读"。速读成本低，还能立刻暴露理解偏差；空手问"你想怎么读"是把决策成本推回给用户。
- 用户说"快速看看值不值得读" → 速读，并且判断要更果断，直接说读或不读。

## 工作流

1. **确认来源与版本**。按 [references/source-handling.md](references/source-handling.md) 处理 PDF / arXiv / DOI / HTML / 粘贴文本。用一句话告诉用户你读的是什么（比如"读了 arXiv v3 的 PDF，共 18 页"），让他们能低成本纠正。
2. **读原文**。先读摘要、引言、方法、实验、结论；图和表必须亲眼看至少一遍——数字和真正的证据在那里，不在正文形容词里。
3. **按模式产出**。结构见 [references/note-template.md](references/note-template.md)；挑局限和可疑点时用 [references/critique-checklist.md](references/critique-checklist.md)，不要机械逐条填。
4. **追加到统一笔记**（用户说不用记时跳过）。用脚本追加，不要手写索引表：

   ```bash
   python3 <skill-dir>/scripts/append_note.py \
     --notes ForMe/阅读记录.md \
     --title "Attention Is All You Need" \
     --year 2017 --venue "NeurIPS" \
     --arxiv 1706.03762 \
     --depth scan --verdict "值得一读" \
     --tags "transformer,attention" \
     --body /tmp/note-body.md
   ```

   正文先写到临时文件（或 `--body -` 从 stdin 读），交给脚本落盘。脚本负责建文件、维护索引、按 DOI/arXiv/标题去重、已有条目时追加"补充"小节，绝不覆盖旧内容。

5. **一句话回报**：读了什么、判断是什么、笔记写到哪。

## 内容原则

这些是笔记有用与没用的分界线，比模板本身更重要。

1. **有据可查。** 关键结论后面跟原文位置（章节号、图/表编号或页码）。笔记的价值在于以后能顺着它回到原文核对，而不是成为一份无法验证的转述。
2. **摘要不是笔记。** 如果一段话和论文摘要几乎一样，它就没有提供新信息。笔记要补的是摘要里没有的：为什么这样做、代价是什么、哪里可能不成立、和你有什么关系。
3. **数字保真。** 引用结果时带数据集、指标、对比对象和单位。宁可写"原文 Table 2 报告提升约 3 个点，但 baseline 未调参"，也不要写"显著提升"。
4. **区分"作者声称"和"证据支持"。** 作者说"显著优于现有方法"是声称；表里只有两个 baseline 且没有方差是证据的边界。两者要分开写，读者才知道该信到哪一步。
5. **写给三个月后的自己。** 省略那些"不读这篇也会知道"的背景，保留那些"不读就会忘"的关键假设、失败模式和直觉。
6. **术语第一次出现时给一句人话解释。** 不是给定义，是给作用："稀疏注意力（只让每个 token 关注一部分位置，用来把长序列的显存压下来）"。
7. **不确定就说。** 原文没写、图看不清、公式推导跳步——直接标注"原文未说明"或"此处推导不完整"。编一个合理答案比留白危害大得多。

## 笔记落在哪里

默认写到 **`ForMe/阅读记录.md`**（相对当前项目根目录）。项目里没有 `ForMe/` 时写到 `./阅读记录.md`；用户指定了别的文件，以用户为准；用户说"不用记"才不落盘。

所有论文共用这一个文件：索引表在最上面，正文按时间追加。不要为单篇论文新建文件，除非用户要求——散落的笔记最后会变成第二个没人打开的文件夹。

同一篇论文再次阅读时，不建新条目，在原条目下追加 `### 补充 · <日期> · <主题>`。发现之前写错了，就明确写"更正：……"，不要悄悄改掉旧内容；错误本身也是理解过程的一部分。

## 边界

- **只有摘要或付费墙挡住全文**：照实说，然后基于摘要给一张"证据有限"的速读卡片，不要假装读过方法和实验。
- **论文很长（>25 页）**：按 [references/source-handling.md](references/source-handling.md) 的取舍策略读，附录只在回答具体问题时补读。
- **扫描件 / 图片版 PDF**：Read 会把页面当图像读，可以识别，但公式密集的页面容易出错；关键数字要交叉核对表格和正文。
- **一次给多篇**：先逐篇速读；需要横向对比时，用同一组字段做一张对比表，但不要把这个 skill 变成文献综述工具。

## 交付前自检

- 第一句是有信息量的判断，还是"本文提出了一种方法"这种空话？
- 有没有至少一个具体数字或图表结论支撑核心判断？
- 局限是否具体到"在什么设置下会失效"，而不是"未来可以继续改进"？
- 速读卡片的判断有没有给出理由和适用人群？
- 三个月后的我，只看卡片能不能决定要不要翻全文？
- 索引表和锚点是否已由脚本更新？
